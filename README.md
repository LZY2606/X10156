# Webhook 投递实验室

在不访问真实接收方的情况下验证 webhook 签名、重试与乱序处理。事件进入虚拟时间队列，
只投递到进程内的可编程接收器（无任何出站 URL 请求）。

## 运行

```bash
./gradlew classes          # 安装检查
./gradlew test             # 全部测试
./gradlew run --args='--host 127.0.0.1 --port 5232'
# 打开 http://127.0.0.1:5232 → “Webhook 投递实验室”
```

可选参数：`--data <目录>`（默认 `./lab-data`）、`--seed <n>`（退避抖动种子，默认 42）。

## 功能

- 端点配置：签名密钥、最大尝试次数、接收器行为（200 / 超时 / 连接断开 / 429+Retry-After /
  500·502·503·504·507 / 已处理但响应丢失），暂停与恢复。
- 事件：按 (端点, 事件 ID) 去重；重试复用事件 ID 与原始 payload，每次生成新的 attempt id 与时间戳。
- 签名：HMAC-SHA256，覆盖实际发送字节与选定请求头（`x-wh-attempt;x-wh-event;x-wh-timestamp`），
  页面可查看规范化请求、签名输入并验证签名。
- 调度：虚拟时钟单步推进；指数退避 + 可注入种子的确定性抖动；Retry-After 支持秒数与 HTTP 日期；
  超过端点上限进入死信；死信可重放（新链指回原链，旧尝试不可变）。
- 暂停只阻止新尝试，不取消已送达接收器的处理；恢复后按原计划顺序执行，不按当前时刻重排。
- 持久化：发送方与接收方状态分别原子落盘；调度写入后、发送前或响应落盘前崩溃，
  重启后结果确定且不丢事件。

## 测试覆盖

签名字节（黄金向量）、429 秒数与 HTTP 日期、确定性退避、提交后丢响应、暂停竞态、
各崩溃点恢复、死信重放、重复事件 ID。
